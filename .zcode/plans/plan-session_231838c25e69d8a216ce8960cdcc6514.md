# macOS 端加入调整图片尺寸（全局配置 + 批量调整）

## 背景

- Rust FFI 与 Swift 模型层已完整支持 resize（`OptimizeOptions.resize: ResizeOptions?`，JSON 契约见 `macos/Bridge/imgo_minifier.h`），缓存 key 也已包含 resize（`CacheStore.describe`）。**无需改任何 Rust 代码。**
- 单图 resize UI 已存在于 `CompareView.TaskOptionsPanel`；缺的是：① 设置 → 转换配置（ProfileEditor）的默认尺寸规则；② 主列表对全部图片的批量调整入口。用户确认两者都要。
- Xcode 工程为 objectVersion 70（文件夹同步组），新增 Swift 文件自动纳入编译，无需改 pbxproj。`macos/Vendor/libminifier_ffi.a` 已预编译，无需重编 Rust。

## 改动清单（全部在 macos/ 内）

### 1. 新建共享控件 `macos/IMGo/Views/ResizeOptionsEditor.swift`
从 CompareView 现有实现抽取的可复用尺寸编辑器：
- 接口：`ResizeOptionsEditor(resize: Binding<ResizeOptions?>, defaultDimension: UInt32)`
- 结构：`Toggle(resize)` + 宽/高 `TextField`（onSubmit 提交，避免逐字符重跑任务）+ 三档分段 Picker（等比容纳 / 等比覆盖 / 拉伸，对应 `DOWNSIZE_CONTAIN/COVER/EXACT`）
- Toggle 关闭 = `resize = nil`；开启 = 以 `defaultDimension` 初始化
- 增加对外部 binding 变化的同步（批量应用时若对比面板开着，UI 跟随刷新；当前实现只有 onAppear 初始化，顺手修复）

### 2. `CompareView.swift` — TaskOptionsPanel 改用共享控件
删除内联的 resize 块（约 60 行），替换为 `ResizeOptionsEditor`，binding 经现有 `applyChange` 路由，重跑语义不变。

### 3. `SettingsView.swift` — ProfileEditor 增加默认尺寸
质量滑块下方插入 `ResizeOptionsEditor(resize: $profile.options.resize)`。
- `GlobalDefaultOptions.options` 本就是 Codable，ConfigStore 持久化与导入时 `defaultOptions` 取默认值均自动生效，无需改模型
- 点「立即应用」走既有 `updateAppOptions(rerunAll: true)` 全量重跑

### 4. `ContentView.swift` — 主窗口头部加批量入口
- 有任务时，头部（清空按钮旁）显示图标按钮（SF Symbol `arrow.down.right.and.arrow.up.left`，help = 批量调整尺寸），点击弹 popover
- popover 内容：`ResizeOptionsEditor` 绑定本地 `@State` + 说明文字（将应用到 N 张图片并重新处理）+「立即应用」按钮
- Toggle 关闭后应用 = 清除所有任务的 resize（恢复原始尺寸输出）

### 5. `AppStore.swift` — 新增 `applyResizeToAllTasks(_ resize: ResizeOptions?)`
遍历 tasks：`task.options.resize = resize; task.result = .idle`，然后 `scheduleProcessing()`，完成后 toast 反馈（复用现有 processId 防竞态机制与含 resize 的缓存 key）。

### 6. i18n — 13 个语言包各加 2 个 key
`batch_resize`（按钮/标题）、`batch_resize_description`（含 `{0}` 数量模板）。其余（resize、宽、高、三模式文案）全部复用现有 key。

## 验证

1. `xcodebuild -project macos/IMGo.xcodeproj -scheme IMGo -configuration Debug build`（与 CI 相同命令）
2. 校验 13 个 i18n JSON 合法性
3. 构建通过后给出手动冒烟步骤（设置面板改 profile 尺寸→应用→任务卡分辨率变化；头部批量按钮→应用到全部）

## 已知但不动的

- `resize_cover_description` 文案写的是"放大"，实际核心 `DownsizeCover` 从不放大小图（`.min(1.0)`），文案与行为有出入——本次不改，避免 13 语言批量改动；如需修正另说。
